# Contributing

Thanks for your interest in `jsonforms-spartan`. The project is pre-alpha and maintained by one person in spare
time, so please open an issue before starting anything larger than a small fix. That way we can agree on the
approach before you spend time on it.

## Before you start

- [ROADMAP.md](./ROADMAP.md) has the plan, the milestones and the Definition of done for renderers (§2).
- [docs/adr/](./docs/adr/) records the architectural decisions. A change that contradicts an accepted ADR needs a
  new ADR, discussed in an issue first.

## Ground rules

These are enforced by lint and CI where possible.

- **No RxJS in library code.** No imports from `rxjs` or `@angular/core/rxjs-interop`, no Observables in the
  public API, and `rxjs` never appears in the package's `dependencies` or `peerDependencies` (ADR-0001).
- **Signal Forms only.** Use `@angular/forms/signals` (`form()`, `[formField]`, `FormValueControl`). No reactive
  forms, no template-driven forms, no `@jsonforms/angular`.
- **Signals everywhere.** Standalone components, OnPush (the Angular 22 default, so never set `Eager`), zoneless.
- **JSON Schema is the only validation contract.** Errors come from AJV. Don't generate Signal Forms validators
  (`required()`, `min()`, …) from the schema.
- **Helm is vendored** in `projects/jsonforms-spartan/src/lib/ui/` (ADR-0002). Never import `@spartan-ng/helm/*`
  in the library, never export anything from `ui/`, and change the snapshot only through `tools/helm-diff`, in a
  PR of its own.
- **Accessibility:** target WCAG 2.2 AA. Every renderer meets the Definition of done in ROADMAP §2.

## Development setup

Requirements: Node.js 24 and npm 11.

```bash
npm ci
npm start            # demo app at http://localhost:4200
```

| Command | What it does |
|---|---|
| `npm start` | Serve the demo app |
| `npm run build` | Build the library to `dist/jsonforms-spartan` |
| `npm run check:dist` | Fail if the built package imports or depends on RxJS or `@jsonforms/angular` |
| `npm run build:demo` | Build the demo app |
| `npm test` | Run all unit and render tests (Vitest) |
| `npm run lint` | ESLint, including the import restrictions above |
| `npm run format` / `format:check` | Prettier |
| `npm run e2e` | Playwright + axe (WCAG 2.2 AA) on the demo; starts `ng serve demo` on port 4300. First run: `npx playwright install chromium` |
| `npm run helm:diff` | Check the vendored helm against the CLI-generated reference (see `src/lib/ui/SNAPSHOT.md`) |

The demo imports `jsonforms-spartan` and `jsonforms-spartan/core` from source through tsconfig path aliases, so
you don't need to rebuild the library while working on the demo.

## Repository layout

```
projects/jsonforms-spartan/
  core/        # jsonforms-spartan/core: the UI-agnostic signal binding
  src/lib/     # jsonforms-spartan: spartan renderers, vendored helm in ui/
projects/demo/ # demo app; reference helm generated by the spartan CLI lives in src/ui/
docs/adr/      # architecture decision records
tools/         # helper scripts
```

## Writing a renderer

One renderer is one folder with:

- a standalone component (selector prefix `jfs-`; `jf-` is for the core binding)
- its `RankedTester`, built from `@jsonforms/core` predicates, with the rank `@jsonforms/angular-material` uses
- a spec covering the tester and the rendering

Check it against the Definition of done in ROADMAP §2 and add a demo entry with a schema and UI schema. Value
conventions follow JSON Forms: for example, `format: date` is a `YYYY-MM-DD` string built from local date parts,
never from `toISOString()`.

## Pull requests

- Branch off `main` (`feat/…`, `fix/…`, `docs/…`, `chore/…`) and open a PR. PRs are squash-merged, so the PR
  title becomes the commit message: use [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat: add number control`).
- CI must pass: format, lint, tests, library build, dist check, demo build.
- Every bug fix comes with a test that fails without the fix.
- Tick the ROADMAP checkboxes your change completes, in the same PR.
- New architectural decisions go in `docs/adr/NNNN-title.md`.
